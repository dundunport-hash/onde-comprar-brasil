# Workflow econômico

1. Identifique exatamente o pedido e a área afetada.
2. Leia 3–6 arquivos do projeto mais prováveis; não faça varredura geral.
3. Faça plano curto.
4. Edite somente arquivos necessários; evite reescrever arquivos inteiros por estilo.
5. Revise o diff e imports/tipos diretamente afetados.
6. Pare quando o pedido estiver atendido.
7. Resposta final: resumo + arquivos alterados + comandos manuais opcionais.

Evite: pesquisas externas, novos pacotes, documentação longa, testes automáticos, árvores completas, leitura recursiva e refactors paralelos não solicitados.
